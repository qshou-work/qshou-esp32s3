# 真机证据：GESTURE_DIR 位移预算修复（静默少走 → 精确送达）

- **日期**：2026-10-01 22:15–22:45
- **设备**：ESP32-S3 开发板（MAC `44:1b:f6:ca:0a:0c`），IP `192.168.160.53`
- **对端**：vivo Y71t，BLE HID（相对鼠标）已连接，`ble_connected=1`
- **测量方法**：`POST /api/v1/gesture` 下发 → 读 `GET /api/v1/health` 的
  `gest_frames / gest_dx / gest_dy / gest_sent / gest_drop`。
  `health` 的净位移**只累加发送成功的帧**，故它是「空中真实位移」的唯一可信口径。
- **安全性**：探测全部使用 `press=0`（纯移动，不按键），不会误触点击/拖拽。

## 1. 修复前（bug 现场）

请求与回包：

```
POST /api/v1/gesture  {"type":"dir","press":0,"dx":2000,"dy":0,"steps":12}
→ 200 {"ok":true,"type":"dir","steps":12,"step_ms":90,"dx":2000,"dy":0,"note":"playing on device"}
```

`health` 实测：

```
gest_frames=14  gest_dx=1524  gest_dy=0  gest_drop=0  gest_sent=14  jit=89/89/90
```

- 请求 2000，实到 **1524 = 12 帧 × 127**，缩水 **476 counts（23.8%）**
- 回包 `dx` 是**请求原值**，不是实际值 → 调用方无法察觉
- `gest_drop=0` 说明不是链路丢帧，而是**帧预算不够**（隐藏的几何截断）

## 2. 修复后（同一请求）

```
→ 200 {"ok":true,"type":"dir","steps":16,"step_ms":75,"dx":2000,"dy":0,
       "budget":2032,"shortfall":0,"note":"playing on device"}

gest_frames=18  gest_dx=2000  gest_dy=0  gest_drop=0  gest_sent=18  jit=74/74/75
```

帧数由固件按位移自动展开到 16（`ceil(2000/127)`），`step_ms` 同步下调 90→75
以锁定总时长，净位移**精确等于请求值**。

## 3. 大位移与极速节奏压测（修复前这些量级完全不可达）

| 请求 | 回包 `steps_eff` / `step_ms_eff` / `budget` | 实测 `gest_dx` | `gest_drop` | 判定 |
|---|---|---|---|---|
| `dx=2000, steps=12` | 16 / 75ms / 2032 | **2000** | 0 | ✅ 精确 |
| `dx=5000, steps=12` | 40 / 30ms / 5080 | **5000** | 0 | ✅ 精确 |
| `dx=10000, steps=12` | 79 / 15ms / 10033 | **10000** | 0 | ✅ 精确（81 帧 / 1.2s） |
| `/swipe` Δ=(0,0)→(200,0) | 16 / 60ms / 2032 | **200** | 0 | ✅ 精确（控制器路径） |

**副产品性能事实**：不推流时 BLE HID 能稳定维持 **15ms/帧 ⇒ ≈67 帧/秒通知且零丢帧**
（81 帧耗时 1.2s，`jit=14/14/15`）。即长距离移动不需要靠「少走」来换取稳定性。

## 4. 关键结论

1. `±127/帧` 是 8-bit 有符号线帧的硬约束，**交付上限 = 帧数 × 127**，与链路质量无关。
2. 凡是**回包 echo 请求值**的接口都在掩盖这类截断。对账口径必须用 `health.gest_dx`。
3. `handle_swipe` 原先写死 16 帧（上限 2032），而控制器在 `[0,10000]` 空间算增量：
   一次全屏移动只交付 20%，**且控制器 `CursorState` 仍照满额更新 → 光标信念与宿主
   真实位置永久失同步**。这是修复前控制器路径最严重的隐性缺陷。
4. 遗留约束（下一步）：`counts ↔ 屏幕像素` 的比率仍未实测 —— 位移现在能精确送达，
   但「移动到指定 SCR 坐标」只保证方向与相对距离，不保证落到指定像素。
   需现场标定一次确定该比率（接缝已在 `shared/coords.Calibration` 预留）。
